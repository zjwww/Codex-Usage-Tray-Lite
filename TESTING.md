## Reproduce

Run on Windows with a suitable .NET SDK:

```powershell
dotnet restore .\CodexUsageTrayLite.sln --configfile .\NuGet.Config
dotnet build .\CodexUsageTrayLite.sln -c Release -p:Platform=x64 --no-restore
& .\tests\CodexUsageTrayLite.Tests\bin\x64\Release\net48\CodexUsageTrayLite.Tests.exe
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\render-readme-menu.ps1
```

The packaging script expects a local SDK at `.tools\dotnet\dotnet.exe`. This development directory is ignored and not distributed. After configuring it, `scripts/package-release.ps1` restores, builds, runs the harness, creates an allowlisted ZIP with internal file hashes and an external ZIP checksum, and rejects an existing package filename. Never overwrite an earlier package.
